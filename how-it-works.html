How it works

The inspector compares a screenshot taken before a change with one taken after it, and outlines what moved, appeared or disappeared. It runs entirely in your browser.

What it does

You give it a baseline (the page before an upgrade, patch or customization) and an after-change screenshot. It highlights unintended visual changes so a tester does not have to spot them by eye.

It is a supplemental quality-assurance tool for the visual-comparison part of testing, not a replacement for functional or security testing. A visual diff can show that a field or button appeared or disappeared for the tested role. It does not prove that authorization is correct.

The steps

  1. Load a sample, or add your own baseline screenshot.
  2. Add the after-change screenshot (drop it, paste it with Ctrl+V, or choose a file).
  3. Press Compare.
  4. Decide each changed region: Expected, Regression or Noise.
  5. Press Save run and fill in the evidence form.
  6. Sign off, then (optionally) promote the after screenshot to be the new baseline.

What happens when you press Compare

  1. Align. If the after screenshot is shifted a few pixels or zoomed slightly, the tool lines it up first and tells you how ("Aligned: shift (0, 3)").
  2. Difference. It subtracts the two pictures pixel by pixel, after a light blur that ignores tiny rendering noise.
  3. Ignore zones. Areas you marked (such as a timestamp) are set to "no difference".
  4. Threshold. Small differences are dropped; larger ones are kept.
  5. Regions. Nearby changed pixels are merged into boxes, and tiny boxes are dropped.
  6. Similarity and heatmap. It also computes SSIM (a 0 to 1 similarity score) and a heatmap of where the picture changed most.

The result is FAIL when there is at least one region and the changed share of the page is above the page's limit (0.1% by default). Otherwise it is PASS.

The technology in plain words

OpenCV.js
OpenCV is a well-known library for working with images. OpenCV.js is the version that runs in a web browser. We use it to align, subtract, and find the changed areas. It is included with the app, so nothing is downloaded from another site.
WebAssembly
A compact, fast format that browsers can run next to JavaScript. OpenCV.js is compiled to WebAssembly, which is why comparing two full-page screenshots takes a fraction of a second.
Web Workers
A worker is a second thread in the browser. The heavy image work happens there, so the page stays responsive and the Cancel button always works. If a comparison takes longer than 30 seconds, the worker is restarted.
IndexedDB
A database built into the browser. It keeps your pages, baselines, ignore zones and saved runs on this device, so they are still there after a refresh. You can inspect it in Chrome DevTools under Application, IndexedDB, erpinspector.

Capture standard

Capture the before and after pages with the same browser, 1366×900 viewport, 100% zoom, test user and data, then promote the after capture only after sign-off.

Capture rules
ItemStandard
EnvironmentThe same test environment for before and after. Never production.
BrowserGoogle Chrome, the same major version for both captures.
Viewport1366 × 900.
Zoom100% browser zoom, with OS display scaling at 100%.
User and roleThe same test user and role for both captures.
Business dataThe same test record, business unit, effective date and period.
ThemeThe same theme (Classic, Classic Plus or Fluid) throughout a cycle.
Page stateFully loaded; no hover, tooltip, open prompt or focus ring.
FormatPNG, full page (Chrome DevTools, Capture full size screenshot). Never JPEG.

File name: <module>_<page>_<before|after>_<YYYYMMDD>.png. The cycle: capture before, apply the change, capture after, compare, triage, sign off, promote.

Reading a result

Four views show the same result: Boxes (numbered outlines on the after screenshot), Side-by-side, Overlay slider (0 is all before, 100 is all after) and Heatmap (blue means no change, red means strong change). The numbered list below the views carries the same information as text.

  • Expected: the change was intended.
  • Regression: an unintended defect.
  • Noise: a harmless difference, such as a timestamp or rendering.

Every region of a FAIL run needs a decision before you can save it. You cannot sign off while any region is marked Regression: log a defect, attach the report, and retest after the fix. Promote the after screenshot to the baseline only after sign-off. The "Likely ..." text next to a region is a suggestion, never a verdict.

Ignore zones

An ignore zone hides a rectangle (a timestamp, a user name) from the comparison. Zones belong to the page and are reused on every later comparison. If zones cover more than 15% of the page, the tool warns you that large ignored areas can hide real regressions.

You can add one three ways: drag on the baseline picture, choose Add ignore zone on a changed region, or use Add zone manually and type the X, Y, width and height (the keyboard route).

Ignore zones hide areas from the comparison. They are not a security control.

Your data and storage

Everything is stored in this browser, in an IndexedDB database called erpinspector. There are no network calls after the page loads, and your screenshots never leave the device.

To wipe it, open Settings and choose Reset app data. If the app says storage is blocked, allow site data for this site in your browser settings, or leave the private window. You can still load a sample and compare, but nothing is kept when you close the tab.

Limits

  • It is a visual check only. It does not test behaviour, calculations or permissions.
  • It needs full-page PNG screenshots captured with the same settings.
  • The demo uses fictional data only ("Demo ERP (fictional)"). Do not load real production screenshots.
  • The time-saving figures in the business case (about 3 minutes by hand versus about 1 minute) are assumptions for a pilot, not measurements.
